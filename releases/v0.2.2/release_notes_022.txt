Resumo
Release v0.2.2 do EdgeHub Client SDK. O port ESP32 deixa de descartar HTTP 401 (EdgeHub usa 401 de aplicação, sem WWW-Authenticate) e lê Retry-After no event de header. Requer edgehub-device-sdk ≥ 1.2.3 (ABI 2).

Port ESP32 — POST 401
     * Sintoma: check-in/telemetria falhavam ou perdiam o body em HTTP 401; o esp_http_client no modo perform() trata 401 como erro de transporte se não houver WWW-Authenticate.
     * Causa: o POST antigo não usava open/write/fetch_headers/read; o 401 de aplicação era descartado.
     * Fix: POST via open / write / fetch_headers / read; Retry-After lido no event de header.

Dependência
     * edgehub-device-sdk ≥ 1.2.3 (identityChallenge em 4xx + parser JSON com espaço após ':').
